Guia de passagem do projeto

Documento para o profissional que vai assumir o site do Classificado Vintage Riders. Leia de cima para baixo: em cerca de 15 minutos você sabe como tudo funciona.

Voltar

1. Resumo

Site de catálogo de motos clássicas com painel de administração. É um site estático (HTML, CSS e JavaScript puros, sem build nem framework) que lê os anúncios de um banco Supabase. Não há servidor próprio para manter.

  • Público: home, catálogo (À venda e Acervo), detalhe da moto, serviços, sobre, contato, privacidade.
  • Painel (/admin): login, criar, editar, ocultar, marcar como vendida e excluir anúncios, com upload de fotos.
  • Suporte: página leosumiu.html (esta passagem de bastão).

3. Como rodar e publicar

git clone https://github.com/leoperon2/vintage-riders-prototipo
cd vintage-riders-prototipo
python3 -m http.server 8000      # abra http://localhost:8000

# depois de editar e testar:
git add -A && git commit -m "descreva a mudança" && git push origin main
  • O GitHub Pages publica o que estiver em main em 1 a 2 minutos.
  • Cache: os links de CSS e JS nos HTML têm ?v=N. Ao alterar um CSS/JS, aumente o número em todos os HTML: sed -i 's/?v=5/?v=7/g' *.html admin/index.html. Sem isso, navegadores podem manter a versão antiga.
  • Os HTML são a fonte da verdade: edite-os diretamente.

5. Banco de dados (Supabase)

  • Tabelas: motos (anúncios), admins (e-mails autorizados a editar) e chamados_leo (pedidos da página de suporte).
  • Situação do anúncio (motos.status): ativo (à venda), vendido (aparece como vendida, sem contato) e oculto (fora do site).
  • Segurança por RLS: o público só lê ativo e vendido; só quem está em admins escreve, edita, exclui e envia fotos (bucket fotos). A chave em js/config.js é pública e é segura por causa disso.
  • Recriar o banco: rode supabase/schema.sql e depois supabase/seed.sql no SQL Editor.
-- novo administrador: 1) Authentication > Users > Add user (e-mail e senha)
-- 2) no SQL Editor:
insert into public.admins (email) values ('novo-admin@exemplo.com');

-- ver pedidos da página de suporte:
select * from public.chamados_leo order by created_at desc;

O administrador provisório da demonstração é admin@vintageriders.demo. Troque a senha e cadastre o e-mail real do cliente.

6. Importação do Instagram

No painel há o botão "Importar novos do Instagram", que hoje só exibe um aviso (depende de contrato). A base técnica existe: scripts/processar_posts.py converte o JSON do Apify (instagram-scraper) em anúncios e fotos otimizadas. Os posts seguem o padrão Marca, Modelo, Ano, Km, Valor, Contato, Cidade, Obs.

Para automatizar: um workflow do GitHub Actions que chama o Apify (token guardado como secret, nunca no repositório) e grava no Supabase evitando duplicar pelo campo shortcode. Alternativa oficial: Meta Graph API, com autorização da conta do cliente.

7. Pendências conhecidas

  • Preencher o contato em js/config.js (campo LEO).
  • Revisar a política de privacidade (veio do site antigo com trechos de modelo e endereço divergente).
  • Confirmar o endereço oficial do showroom (o site antigo tinha três).
  • Confirmar quais motos do acervo estão vendidas.
  • Trocar a senha do administrador provisório.
  • Configurar o domínio definitivo e redirecionamentos do site antigo.
  • Avaliar plano pago do Supabase (o gratuito pode pausar por inatividade).
  • Revisar os textos das dúvidas frequentes com o cliente.

8. Checklist de transferência de acessos

O titular de cada conta precisa fazer (ou autorizar) estes passos. Sem isso, o novo profissional não consegue publicar nem acessar o banco.

  • GitHub: transferir o repositório (Settings > Danger Zone > Transfer) ou adicionar o profissional como colaborador.
  • Supabase: transferir o projeto para a organização do cliente ou convidar o profissional como membro.
  • Domínio: acesso ao registro e ao DNS.
  • Google Analytics e demais contas que o cliente já usa.
  • Administrador do painel: cadastrar o e-mail do cliente e trocar a senha provisória.
  • Qualquer chave secreta futura (Apify, e-mail transacional): guardar em gerenciador de senhas e em secrets, nunca no código.

9. Boas práticas

  • Nunca versionar a chave service_role do Supabase nem senhas.
  • Antes de mudar tabelas, exporte um backup (Table Editor > Export) e teste num projeto separado.
  • Mantenha as regras RLS ligadas em todas as tabelas.
  • Teste no celular: a maior parte do público e do painel usa Android.

Dúvidas sobre decisões do projeto: contato do Léo em js/config.js (campo LEO).
